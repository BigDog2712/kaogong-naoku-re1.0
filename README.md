## ✨ re1.0 新增功能

> 在 [原项目 GongkaoNaoku](https://github.com/jangviktor-web/GongkaoNaoku) 的基础上，围绕「做题手感、学习反馈、复习陪伴」做了以下增强：

| 功能 | 说明 |
| :--- | :--- |
| 🖌️ **画笔与划线** | 支持多端画笔，可放大图片后自由批注；PC 端支持框选划线——左键框选即可对文字划线，适合标记材料与解析重点 |
| ⏱️ **学习计时** | 对复习与做题分别计时，自动汇总为「今日学习时长」与「总学习时长」，学习投入一目了然 |
| ✅ **边做边对 / 先做后对** | 新增两种刷题模式，参考粉笔刷题体验，既可选即时反馈也可选整套完成后再统一核对 |
| 🤝 **陪伴模式** | 允许他人读取你的学习数据并进行简单对话，把独自刷题变成结伴学习 |
| 📅 **复习模式优化** | 复习界面新增「已复习天数」显示，坚持天数看得见 |
| 🩹 **题库与同步修复** | 删改部分题目参考文献不一致之处；修复部分设置在多端无法同步的问题 |
| 🚫 **丢弃题目** | 练习时可一键丢弃不想刷的题，立即移出本组队列，所有抽题模式自动跳过；真题浏览里可随时找回并恢复 |
| 🎯 **复习直答自评** | 复习时无需先揭示选项与解析，直接点「忘记 / 困难 / 一般 / 熟悉」即写入记忆曲线并跳下一题，键盘 `1`–`4` 同样可用 |
| 🌈 **细腻练习热力图** | 热力图升级为 8 档分位配色（青 → 翠绿 → 金），并显示练习天数、总题量与最猛的一天 |
| 🔧 **其他更新** | 细节体验与稳定性持续改进 |

## ⚠️ 关于演示站

本项目有一个线上演示站，**仅供演示，不建议长期使用**：

- 它跑在 WorkBuddy 沙箱上，**服务器资源有限，无法支撑多人同时在线**；人多时页面会明显卡顿，甚至打不开；
- 演示数据随时可能被清空或重置，**不适合存放正式学习进度**；
- 也就是说：你可以点进去看看效果，但别把它当自己的学习环境。

**想要一个属于自己的稳定实例？三步，不用装任何东西：**

1. 复制本仓库地址 `https://github.com/BigDog2712/GongkaoNaoku-re1.0`；
2. 打开 [WorkBuddy](https://www.workbuddy.ai)，新建会话，把地址发给 AI 助手，让它帮你部署成在线应用；
3. 等几分钟，你会拿到一个**只属于你的在线应用地址**，自己用或分享给同学都行。

## 发布前数据保护检查

每次向 WorkBuddy 或其他托管环境上传更新，按此顺序执行；此检查不能由 `.gitignore`、`data/` 分离或服务端自动快照替代。

1. 登录生产实例的管理员账号，设置页「管理员：全库快照」点击「立即创建快照」。
2. 在快照列表点击「下载」，把最新全库 `.db` 取回本机，并确认浏览器下载完成、文件非零；记录文件名/日期。不要把它放进项目目录、Git 仓库或发布压缩包。
3. 确认备份文件保存在源码目录以外；高价值数据再复制一份到另一块磁盘或受控云存储。
4. 检查准备上传的目录/压缩包中不存在 `users.db`、`data/users.db`、`dev-data/users.db`、`data/backups/` 或任何用户库副本。仅靠 `.gitignore` 不够，发布器可能上传整个目录。
5. 确认前 4 项完成后再上传代码。更新后使用现有账号登录，核对账号与数据；异常时停止后续操作并从本机备份恢复。

**硬性规则：本机备份未下载并核验前，不执行上传、发布或全库恢复。** README 中的流程是人工门禁；若所用发布工具没有可配置的 pre-deploy hook，不能声称工具已经自动拦截发布。

## 为什么不是直接刷题

行测真题的难点从来不是"没做过"，而是**做过的第 8 天就忘了**。本应用的核心不是题库，而是那套排程：

- 每道题有独立的记忆状态（间隔、难度系数、复习次数、上次结果）
- 到点才推给你，不到点绝不打扰
- **答错或忘记的题会自动缩短间隔**，反复出现直到稳住
- 你只需做一件事：答完自评"我记住了多少"

题库只是载体，真正的产品是**复习的那条时间线**。

## 快速开始

> 🚀 **不想安装？** [先打开线上版体验一下](https://a2de5e308362285fb.app.workbuddy.host/)——注册账号或点「游客模式」，10 秒开刷。觉得好用再回来自建，数据完全本地。

```bash
git clone https://github.com/BigDog2712/GongkaoNaoku-re1.0.git   # 本仓库（re1.0 增强版）
cd GongkaoNaoku-re1.0
python3 assemble_db.py   # 合并分卷题库，生成 kaogong.db（约 10 秒）
python3 server.py        # 启动
```

或者克隆原项目（不含 re1.0 增强功能）：

```bash
git clone https://github.com/jangviktor-web/GongkaoNaoku.git   # 原项目
cd GongkaoNaoku
python3 assemble_db.py   # 合并分卷题库，生成 kaogong.db（约 10 秒）
python3 server.py        # 启动
```

浏览器打开 <http://127.0.0.1:8300>。

> **Windows 用户**：直接双击 `启动考公系统.bat`，浏览器会自动打开。关掉那个黑色窗口即停止服务。
> **Linux / macOS**：`bash start.sh`。

首次打开会让你选择：**注册账号**（换设备也能接着学）或 **游客模式**（点一下直接用，不填任何信息）。

## 功能地图

| 模块 | 做什么 |
| :--- | :--- |
| **总览面板** | 今日待复习 / 未学新题 / 已练 / 错题数 / 收藏数，各模块进度条，掌握度分布（学习中·初记·短期·长期·稳固） |
| **开始练习** | 按模块 / 大类 / 考点筛选出新题，逐题作答 → 看深度标注 → 自评记忆强度 |
| **复习到期** | 记忆引擎推送的当日复习队列。先回忆，再核对，再自评 |
| **错题本** | 自动收集所有答错的题，支持「只练错题」集中攻克，稳定后自然淡出 |

| **材料组题** | 资料分析按同一段材料成组出题（1,578 组），贴近真实考场节奏 |
| **疑点复核** | 汇总所有标注「官方解析可能有误」的题，逐条复核并标记 |
| **数据统计** | 连续打卡天数、每日目标环、近半年热力图、各模块正确率、薄弱考点排行 |
| **真题浏览** | 六模块全量筛选：地区 / 年份 / 关键字 / 复习状态 / 下次复习日 |
| **考点导航** | 按考点横向对比不同省份的同类考法，一键「练同类题」 |

**外观**：主题三态循环（暗色 / 亮色 / 跟随系统）、字号 14–19px 可调、专注模式隐藏侧栏居中窄列。

真题以各考试当年**考生回忆版**为基础整理（这也是全国公考题库的通行做法），个别年份早期题量较少属正常现象。

## 每道题都带什么

不是只有题干和答案。解析由程序从原始题库逐题抽取，每道题包含：

`问法模型` · `推理链` · `⚡最快解法` · `⚠易错点` · `🧩母题抽象` · `给定材料` · `官方解析` · `❓疑点待复核` · `📝个人笔记` · `⭐收藏`

## 记忆引擎：SM-2 怎么运作

作答后按真实记忆强度自评四档，系统据此重算这道题的**下次出现时间**：

| 自评 | 含义 | 引擎行为 |
| :--- | :--- | :--- |
| **忘记** | 完全没印象 | 今天重来，退回学习期 |
| **困难** | 想起来了但很吃力 | 间隔缩短，难度系数下调 |
| **一般** | 正常记住 | 标准间隔增长（1 → 6 → ×难度系数…） |
| **熟悉** | 轻松秒答 | 间隔拉长，难度系数上调 |

**键盘流**：作答时 `A/B/C/D` 选选项，`空格` 看标注；自评 `1/2/3/4` 对应 忘记/困难/一般/熟悉。

## 多账号与隐私

服务端按账号隔离数据，一套部署可多人使用，互不可见。

| 身份 | 说明 |
| :--- | :--- |
| **注册账号** | 用户名 + 密码登录（PBKDF2-HMAC-SHA256 加盐哈希），凭账号在任何设备续上进度 |
| **游客模式** | 免注册进入，自动获得一个云端匿名身份；**换浏览器或清缓存即为全新身份**。设置页可随时升级为正式账号，数据不丢；退出即销毁，不留残留 |

题量与进度都存放在服务端 SQLite，浏览器只保存一枚登录令牌。

## 账号、管理员与数据安全交接说明

> 本节是后续维护和代码 agent 的操作边界。**禁止将用户库当作可重建缓存处理**；代码升级、前端重构、题库更新都不应删除、覆盖或重置用户库。

### 项目与数据结构

- `server.py`：HTTP API、认证、SQLite 用户库建表/迁移、备份与管理员操作。
- `static/app.js`、`static/index.html`、`static/style.css`：原生 JS 单页应用与静态资源。改动前端后同步更新 `index.html` 中的 `kg-app-ver`、CSS/JS 查询版本，触发浏览器缓存更新。
- `kaogong.db`：题库，只读挂载；不得用于保存账号或学习进度。
- 用户数据默认位于 `data/users.db`；`KAOGONG_USER_DB` 可将其指向其他位置（本地开发建议独立目录）。旧根目录 `users.db` 仅由启动迁移逻辑兼容处理。
- `data/backups/`：**唯一**的备份根目录，只存在于服务端。按用户库真实路径哈希建立 `kaogong-<实例标识>/` 子目录：下面 `users-*.db` 是全库快照，`accounts/<uid>/account-YYYYMMDD.json` 是单账号云端快照。v1.7.0 起不再支持自定义备份路径，升级时旧路径里的快照会被收归到这里并删除相关设置。

用户库包含 `users`、`sessions` 等账号/会话表，以及 `srs`、`reviews`、`notes`、`favorites`、`doubt_status`、`exam_history`、`study_time`、`discarded`、`user_settings`、练习记录和陪伴关系等用户数据表。`settings` 保存全局维护标志和备份配置。表结构以 `ensure_tables()` 与 `migrate_v2.py` 为准，改表必须可重复运行且保留旧字段/旧数据。

### 初始管理员与权限

- 新建空库首次启动时初始化 `admin` 管理员，初始用户名/账号 `admin`，初始密码 `123456`。首次登录后应立即修改密码及名称；用户名可在管理员面板修改。
- `role='admin'` 仅用于授权管理账号与全库备份；所有这些接口都在服务端校验 token 和角色，前端隐藏面板不构成安全边界。
- 管理员可修改自己或其他账号的名称、用户名、密码；普通账号仍只能管理自己的资料。删除账号会删除其学习数据，操作不可撤销；不可删除当前管理员或最后一个管理员。
- 若数据库已有账号但缺少初始化标记，升级逻辑必须保留现有账号并补建管理员，不得误认为新安装而清库。首次空库初始化之外，不得自动重置账号。
- 只有经用户明确确认并完成备份后，维护人员才可设置 `KAOGONG_FORCE_BASELINE=1` 强制重置账号；`KAOGONG_SKIP_BASELINE=1` 可跳过该逻辑。不要把这些变量常态化配置到生产环境。

### 备份与恢复

> 设计原则：**备份只存服务端，入口只留两个。** 个人侧只有「云端快照」和「本地 JSON」；管理员侧只有「全库快照」。不再有备份目录配置，避免出现"配了路径但其实只有服务器能写"的误解。

- **全库快照（管理员）**：后台每天 0 点后创建一份全库 SQLite 一致性快照，写入 `data/backups/kaogong-<实例标识>/users-*.db`，保留最近 7 份；写入后执行 `PRAGMA integrity_check`，校验失败的文件会被删除并重试。是否已做用 `settings.last_daily_snapshot` 记日期判断，因此 0 点服务未运行也能在启动后补做当天那份，不会漏天。失败每 60 秒重试。
- 管理员设置页可「立即创建快照」「下载」「删除」；「恢复」会先用当前库生成一份 `-prerestore` 保护快照，再校验目标快照完整性与 `users` 表存在性，随后整库替换。全库恢复会替换全部账号及学习数据，须核对时间与文件后再执行。
- **个人云端快照**：存在 `data/backups/kaogong-<实例标识>/accounts/<uid>/account-YYYYMMDD.json`，按账号物理隔离，一个账号一天一份，保留最近 7 天。每日自动生成，也可「立即保存到云端」，并支持下载 / 恢复 / 删除。列表、下载、恢复、删除都从登录 token 取 uid，不接受前端指定他人 uid；路径穿越式文件名一律 400。
- **个人本地备份**：设置页「导出到本机（.json）」把本人复习进度、复习历史、错题计数、收藏、笔记、疑点、弃题、考试记录、每天学习时长存成本机文件；「从本机文件恢复」按 qid 合并，同题取较新的记录，不会覆盖更新的进度。
- 删除账号（管理员删除或本人注销）会同时删除该账号的云端快照目录，账号没了不会在服务器上留下数据残留。
- 快照是整库副本，包含全部账号；账号隔离仍由业务表的 `user_id`/`uid` 查询条件保证。普通账号的云端快照与本地 JSON 只含本人数据。
- 发布或上传更新前，必须先「立即创建快照」并「下载」全库快照到本机、核验文件非零，之后才可执行上传。下载失败或无法确认文件时停止发布。
- 管理员可在设置页发布公告或更新说明。每次应用前端版本号变化时，服务端会自动发布内置更新说明；每个账号单独记录已确认的公告 ID，点击「知晓」后不再重复显示该公告。管理员发布新公告会生成新 ID，因此会再次通知所有账号。
- 建议升级前执行一次管理员全库备份，并定期把备份复制到与应用主机不同的设备/存储。备份目录权限应仅对服务维护者开放。

### 维护注意事项

1. 发布/升级只更新代码和题库，绝不删除 `data/`、`dev-data/`、`users.db` 或备份目录；不要用开发机用户库覆盖线上库。
2. 禁止执行 `KAOGONG_FRESH=1`、重建/替换用户库、手工删除账号表等会清空用户数据的操作，除非用户明确要求且已验证备份可恢复。
3. SQLite 文件复制应使用数据库 backup API 或停止服务后复制，不要在并发写入时直接覆盖正在使用的数据库文件。
4. 数据库迁移要使用事务、可重复运行、先快照，并验证旧版本数据及登录功能；题库导入不得写入用户库。
5. 密码只保存 PBKDF2 哈希，任何接口/日志/备份 UI 都不得输出明文密码或密码哈希。
6. 初始化默认密码是公开的引导凭据，不适合公网长期使用；管理员首次登录后立即修改。生产环境应限制注册与服务访问面。

### 看什么

| 区块 | 内容 |
| :--- | :--- |
| 指标卡 | 今日活跃 / 今日答题 / 正式账号数 / 今日新增，各带 7 天、30 天对照 |

| 最近活跃账号 | 近 7 天有答题的账号，只显示昵称、类型、最近答题时间、累计题量 |
| 题库与存储健康 | 题量、完整性自检、进度行数、缺解析题数、库文件大小、日志模式、模块分布 |

### 安全设计

| 措施 | 说明 |
| :--- | :--- |
| 口令不进代码 | 只从 `OPS_TOKEN` 环境变量读；少于 16 位视为未配置 |
| 会话与用户体系隔离 | 面板会话只存进程内存（8 小时过期、上限 32 个），**普通用户 token 无效** |
| 暴力猜解防护 | 同 IP 10 分钟内 8 次失败即锁；每次失败额外延迟 0.4 秒；常数时间比对 |
| Cookie | `HttpOnly` + `SameSite=Strict` + `Path=/ops` |
| 接口只读 | 全部接口只有 `SELECT`，**没有任何写库路径** |
| 页面不被收录 | `<meta name="robots" content="noindex,nofollow">` |

> 面板重启即失效（会话在内存里），部署更新后需要重新输入口令，属预期行为。

## 常见问题

**换浏览器后进度不见了？**
注册账号后用用户名登录即可续上。游客模式的身份绑定在浏览器本地，换设备即为新身份——这是设计如此，不是丢数据。

**能不能多人共用？**
可以。各自注册账号，学习进度、笔记、收藏完全隔离，互相看不到对方的存在。
前提是**你自己部署的实例**——本项目那个公开演示站因服务器资源有限，人一多就会卡，见[关于演示站](#关于演示站)。

**占多大地方？**
代码不到 200KB。题库数据库（约 148MB，30MB×5 分卷）与配图（199MB）随仓库提供，**`git clone` 全部到手**，克隆后跑一次 `python3 assemble_db.py` 合并数据库即可，无需自备题库。你的学习数据另存于 `users.db`，首次启动自动生成、初始不到 1MB。

**需要联网吗？**
完全不需要。零第三方依赖、零 CDN、零外部字体，断网照常用。

**上游题库 58,890 题，为什么这里只有 27,506 题？**
上游的 58,890 是「题目行数」——联考同一道题会以几十个省卷的名义重复收录（平均每题 2.32 套卷，最多一道被 778 套卷收录）；按题去重后上游只有 25,382 道不同的题，本项目覆盖其中 25,271 道（**99.56%**），另有 158 道上游没有的更早年真题。不是漏题，是把「卷 × 题」去重成了「题」，更适合刷题与复习。逐题核查数据见 [题量差异说明](#素材来源与致谢)。

3. 记录本次快照文件名和下载日期。不要将含账号密码哈希的全库数据库提交到 Git、上传到公开仓库或放入待发布源码包。
4. 确认本机文件存在后，再 `git pull` 拉取代码并发布。发布后用现有账号登录，核对账号数量和学习数据；发现异常时立即停止进一步发布，使用管理员页面从已下载的快照恢复，或联系部署维护者。

如下载按钮不可用或本机文件无法确认完整，**不要继续发布**。先通过受控运维方式下载服务端快照或联系维护者；不要尝试用本地 `dev-data/users.db` 替代线上库。

**本地自托管的更新方式**：更新前停止服务，用 SQLite backup API 对 `KAOGONG_USER_DB` 指定的实际用户库做一致性备份；确认备份文件完整且不为空后再更新代码。服务端快照只会留在运行服务的机器上，不会自动传到管理员本机。

> ⚠️ **数据位置隔离仍然重要**：自 v1.5.0 起，线上默认使用 `data/users.db`，本地启动脚本应使用独立的 `dev-data/users.db`。发布包不得包含任何环境中的用户库或备份文件。隔离可降低覆盖概率，但不能取代发布前下载到本机的备份步骤。

### 本地自托管 vs WorkBuddy 在线部署

| | 本地自托管 | WorkBuddy 在线部署 |
| :--- | :--- | :--- |
| 适合谁 | 只有自己用 | 想分享给同学/群友一起用 |
| 安装 | 需 Python 3.8+ | 零安装，浏览器即用 |
| 数据位置 | 题库 `kaogong.db`（只读）+ 用户库 `data/users.db` | 服务端 SQLite（`data/users.db`），换设备登录不丢 |
| 访问 | `http://127.0.0.1:8300` | 公网 URL，手机也能开 |
| 备份 | 使用 SQLite backup API 备份实际用户库 | 管理员可下载全库快照到本机；每次发布前必须完成下载并核验 |

> 💡 **数据安全提示**：题库（`kaogong.db`，只读不改）与学习数据（`data/users.db`）分库存放，但线上完整备份必须从服务端快照下载到本机；服务端自动快照本身不是异机备份。
> 旧版根目录的 `users.db` 会在首次启动时自动迁移到当前用户库路径，启动时务必检查迁移日志并确认数据账号数。
>
> 🛟 **多层备份**：
> ① 服务端每日快照 —— 每天 0 点后自动为全库和每个账号各留一份，各保留 7 份（0 点停机也会在启动后补做）；
> ② 每次发布前由管理员「立即创建快照」并下载全库快照，在本机核验后保存在应用目录之外；
> ③ 个人云端 / 本地备份 —— 设置页「💾 备份与恢复」上方是账号云端快照（可下载、恢复、删除），下方可把**本人**数据导出成 JSON 存到自己电脑，换设备 / 误清空 / 换服务器时都能找回（同题以较新记录为准，不会覆盖更新的进度）。
>
> ⚠️ 题库版权归原作者，部署后的站点**仅限个人与小范围学习交流**，请勿公开传播真题内容。

<summary><b>📌 为什么上游 58,890 题，这里只有 27,506 题？（逐题核查报告，打消"漏题"疑虑）</b></summary>

<br>

**一句话结论：不是漏了题，是两种计数口径。** 上游的 58,890 是「题目行数」——一道题出现在几套卷里就计几次；本项目的 27,506 是「去重后的题目数」。我们把上游仓库全部 2,956 份试卷、58,890 行题目逐题解析，与本地 27,506 题逐条比对（题干 + 配图 + 选项 + 材料四重指纹），账目如下：

| 核查口径 | 上游 xingcezhenti | 本项目 考公脑库 |
| :--- | --: | --: |
| 标称题量（题目行，含跨卷重复收录） | 58,890 | 27,506 |
| **按题目去重后（不同题的道数）** | **25,382** | **25,429** |
| 两边都有的同一道题 | — | 25,271 |
| **上游有、本项目缺** | — | **111 道（占上游 0.44%）** |
| 本项目有、上游没有 | — | 158 道（2008–2015 更早年真题等） |
| **对上游唯一题的覆盖率** | — | **99.56%** |

**58,890 的"水分"有多大？** 公考真题大量来自多省同日联考——同一套题会以几十个省份的名义各自成卷、反复收录：

- 平均每道题被 **2.32 套卷**收录；
- 被 5 套以上卷子收录的 2,870 道题，单独贡献了 28,135 行——**占 58,890 的近一半**；
- 最极端的一道通用问法题，被 **778 套卷**收录。

真实例子：2019 年 420 联考的同一道片段阅读题，在上游以 20 多个省份卷的名义各计一次；本项目只保留 1 道，并保留可溯源的试卷信息。

**那 111 道缺口是什么？** 高度集中在天津（83）、河北（15）、广东（13）三地，且每道在上游都只被 1 套卷收录，属边缘题——资料分析 **100% 全覆盖**，判断推理、数量关系各缺 1 道，不影响任何模块的练习完整度。

**两种口径，各有各的用途：**

| | 上游（按卷收录） | 本项目（按题去重） |
| :--- | :--- | :--- |
| 题量 | 58,890 行 | 27,506 道 |
| 适合 | 在 Obsidian 里逐卷翻阅原卷、整卷模拟 | 不重复地刷题 + SM-2 间隔复习 |
| 同一道联考题 | 出现 20+ 次（每省卷一次） | 只出现 1 次，标记全部出处 |

> 验算：25,271（共有）+ 111（缺）= 25,382（上游唯一题）✓；25,271 + 158（本项目独有）= 25,429（本项目唯一题）✓。另外本地 27,506 行中有约 2,077 行是「题干文字相同、但配图或材料不同」的组题行（图形推理、资料分析的固有形态，不是重复），完全重复仅 5 行，已可忽略。

## 题库数据从哪来（已随仓库提供）

`kaogong.db` 纯题库（约 148MB，30MB 分卷随仓库提交）和 `90-图片/`（199MB）已经随仓库提供，**克隆即可用，里面已含 27,506 道题**；你的学习数据存于 `users.db`，首次启动服务时自动生成。

题库收录自公开渠道整理的「考公真题整理」Vault——**506 份试卷、2008–2026 年、31 个省区市 + 国考 + 选调 + 联考**的行测真题，试卷以各考试当年考生回忆版为基础整理。详细构成与完整地区/年份分布见上文 [题库来源明细](#题库来源明细)。

```bash
git clone https://github.com/BigDog2712/GongkaoNaoku-re1.0.git    # 本仓库（re1.0 增强版）
cd GongkaoNaoku-re1.0
python3 assemble_db.py   # 合并分卷题库 → kaogong.db
python3 server.py
```

仅当你**想从原始题库更新内容**时才需要 `parse.py`：设置 `KAOGONG_VAULT` 指向原题库 Vault 后运行，产出纯题库——学习进度存于 `users.db`，与题库更新完全无关。
