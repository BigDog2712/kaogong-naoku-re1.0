## 这是什么

考公脑库是一个自己部署、自己用的行测刷题系统。

题库里有 27,778 道行测真题，覆盖 2008–2026 年的国考、31 个省区市的省考，以及选调生和深圳市考、广州市考。每道题都带审题路径、最快解法、易错点和个人笔记位。

它主要解决一件事：做过的题会忘。所以每答完一道题，你自评一次"记住了多少"，系统用 SM-2 算法算出这道题下次该在什么时候出现。答错的题间隔变短，很快再见到；答得稳的题间隔拉长，一两个月才出现一次。你不需要自己安排复习计划。

技术上没有第三方依赖：后端是 Python 标准库写的 HTTP 服务和 SQLite 单文件，前端是原生 JS 单页应用。不用联网，不用装数据库，克隆下来就能跑。

## 题库

**506 份试卷，2008–2026 年，31 个省区市加国考、选调、市考，共 27,778 道题。** 其中 27,458 道来自 2016 年以后的试卷，是练习主力。

| 模块 | 题量 | 占比 |
| :--- | --: | --: |
| 判断推理 | 7,749 | 27.9% |
| 言语理解与表达 | 7,229 | 26.0% |
| 常识判断 | 4,844 | 17.4% |
| 资料分析 | 3,649 | 13.1% |
| 数量关系 | 3,223 | 11.6% |
| 政治理论 | 1,084 | 3.9% |
| **合计** | **27,778** | **100%** |

每道题都带地区、年份、试卷名三个字段，可以在「真题浏览」里任意组合筛选，也可以溯源到具体试卷，例如「2024年江苏公务员录用考试《行测》题（A类）」。真题以各考试当年的考生回忆版为基础整理，这是国内公考题库的通行做法，个别早年题量偏少属正常。

按考试类型、地区、年份的完整分布，见 [docs/题库构成.md](docs/题库构成.md)。

此外可以另挂**导入题库**：整本拆出来的题（目前是「四海公考 · 逻辑填空600题（2026）」，30 套 × 20 题）合并进题库时，用 `build_qbanks.py` 生成 `qbanks.json` 记下「题库 → 自己的分类 → 成员题号」，「真题浏览」里就能按题库和它的题集单独翻阅。导入题库的题没有地区、年份、考点名，列表和题头显示「题库 · 题集 · 第 N 题」。

> **题库改动只留在本地。** 自行拆书、替换解析或新增题目属于题库内容改动，不在 Apache-2.0 范围内，不得提交或上传到 GitHub，详见[许可](#许可)。

这不是漏题，是两种计数方式。

上游 [ERRRC/xingcezhenti](https://github.com/ERRRC/xingcezhenti) 的 58,890 是「题目行数」：一道题出现在几套卷里就算几次。公考真题大量来自多省同日联考，同一道题会以几十个省份卷的名义反复收录，平均每道题被 2.32 套卷收录，最极端的一道题出现在 778 套卷里。

按题目去重后，上游实际有 25,382 道不同的题。本项目覆盖其中 25,271 道，覆盖率 99.56%，另外还有 158 道上游没有的更早年真题。

| 核查项 | 数量 |
| :--- | --: |
| 上游题目行数 | 58,890 |
| 上游按题去重后 | 25,382 |
| 两边都有的同一道题 | 25,271 |
| 上游有、本项目缺 | 111 道（占上游 0.44%） |
| 本项目有、上游没有 | 158 道 |
| 对上游唯一题的覆盖率 | 99.56% |

缺的 111 道集中在天津 83 道、河北 15 道、广东 13 道，每道在上游都只被一套卷收录，属于边缘题。资料分析覆盖率 100%，判断推理和数量关系各缺 1 道。

验算：25,271 + 111 = 25,382；25,271 + 158 = 25,429。完整核查过程和缺题清单见 [docs/题库差距核查报告.md](docs/题库差距核查报告.md)。

## 复习怎么排

每题答完后自评四档，系统据此重算下次出现的时间：

| 自评 | 含义 | 引擎行为 |
| :--- | :--- | :--- |
| 忘记 | 完全没印象 | 当天重来，退回学习期 |
| 困难 | 想起来了但很吃力 | 间隔缩短，难度系数下调 |
| 一般 | 正常记住 | 间隔按 1 → 6 → 乘难度系数增长 |
| 熟悉 | 轻松答上来 | 间隔拉长，难度系数上调 |

键盘操作：`A/B/C/D` 选选项，`空格` 看标注，`1/2/3/4` 对应忘记、困难、一般、熟悉。

## 每道题有什么

题干和答案之外，解析由程序从原始题库逐题抽取，包括：

问法模型、推理链、最快解法、易错点、母题抽象、给定材料、官方解析、疑点待复核、个人笔记、收藏。

**AI解析**（`ai_json` 字段）是最上面那一块，成表格展示：题干骨架 → 逐项判定（每个选项为什么选 / 为什么排除，✓ 入选绿、✗ 排除红）→ 可迁移方法 → 避坑提醒 → 可直接抄进错题本的笔记。它存在数据库里而不是图片里，所以能全文搜索、能复制文字、手机上自动折行。没生成过 AI 解析的题，这一块不出现，不影响原有解析。

本次随版本已为本地题库批量生成 **17,132 题** AI 解析，覆盖全部无配图题；含图题按约定跳过。这份数据只写题库、不碰用户库，且属于题库内容改动，按许可不进 GitHub 仓库（详见下方生成方法与[许可](#许可)）。

## AI 解析怎么生成

AI 解析不是随题库附带的，要自己跑一次（或分批跑）。脚本是 `build_ai_analysis.py`，走任意兼容 OpenAI 协议的接口（DeepSeek / 通义 / 智谱 / OpenAI 都行）。

```bash
# 1. 配好 key（只在当前终端生效，不写进任何文件）
export AI_API_KEY=sk-xxxxxxxx
export AI_BASE_URL=https://api.deepseek.com/v1   # 可选，默认就是这个
export AI_MODEL=deepseek-chat                    # 可选

# 2. 先看各模块覆盖率
python build_ai_analysis.py --stats

# 3. 试跑一题，只打印不写库，确认效果和费用
python build_ai_analysis.py --limit 1 --dry

# 4. 小批量试点
python build_ai_analysis.py --module 言语理解与表达 --limit 30

# 5. 全量（断点续跑：已生成的自动跳过，中断了重跑同一条命令即可）
python build_ai_analysis.py --all --workers 6

# 想重做已经生成过的
python build_ai_analysis.py --module 言语理解与表达 --force --limit 30

# 顺带导出一份 JSON 备份
python build_ai_analysis.py --all --workers 6 --out ai_analysis_backup.json
```

也可以不走 API：按 `ai_analysis_试点.json` 的格式自己写（或从别处生成），再导入。

```bash
python import_ai_analysis.py 你的文件.json --model manual-v1
python import_ai_analysis.py 你的文件.json --dry     # 只校验不写库
```

JSON 结构：

```json
[{"qid": "2047698", "ai": {
  "v": 1, "answer": "C", "summary": "一句话考点与结论",
  "blocks": [
    {"t": "题干骨架", "type": "text",  "x": "把题干翻译成逻辑式或解题纲领"},
    {"t": "逐项判定", "type": "table", "head": ["选项","判断","依据"],
     "rows": [["A","✗ 排除","引用原词的理由"],["C","✓ 入选","…"]]},
    {"t": "可迁移方法", "type": "steps", "x": ["第1步 …","第2步 …"]},
    {"t": "避坑提醒",   "type": "warn",  "x": ["坑一 …"]},
    {"t": "笔记",       "type": "note",  "x": "可直接抄写的一段"}
  ]}}]
```

`type` 支持 `text` / `table` / `steps` / `warn` / `note`，前端 `aiAnalysisHtml()` 负责渲染，改样式不用重新生成内容。

几点提醒：

- 跑脚本前先停掉 `server.py`，SQLite 同一时刻只允许一个写者。
- 含图的题（图形推理、资料分析选图）模型看不到图，脚本会让它依据题干文字与官方解析反推思路，结果里会注明「图形细节以原题为准」，这类题的 AI 解析只当辅助。
- 全量约 2.8 万题，按每篇 2–3 千 token 估，费用取决于你选的模型单价，先用 `--limit 30` 跑一批看账单再放量。
- 生成结果写进题库 `kaogong.db` 的 `ai_json` 列，**不动用户库**，学习进度和笔记不受影响。

## 安装

不需要安装。确认本机有 Python 3.8 以上版本，然后：

```bash
git clone https://github.com/BigDog2712/kaogong-naoku-re1.0.git
cd kaogong-naoku-re1.0
python3 assemble_db.py   # 合并分卷题库，生成 kaogong.db，约 10 秒
python3 server.py        # 启动
```

浏览器打开 <http://127.0.0.1:8300>。

Windows 用户可以直接双击 `启动考公系统.bat`，浏览器会自动打开，关掉黑色窗口即停止服务。Linux 和 macOS 用 `bash start.sh`。

第一次打开会让你选：注册账号（换设备也能接着学），或者点游客模式直接用。

**题库已经随仓库提供。** 数据库按 30MB 分卷提交（`kaogong.db.part-00` 到 `part-04`），配图在 `90-图片/` 目录，克隆后跑一次 `assemble_db.py` 就能合并出完整的 `kaogong.db`（Windows 双击 `合并题库.bat`）。用户库 `users.db` 不用手动创建，首次启动时自动生成，账号、做题记录、收藏、笔记都在里面。

只有想从原始题库 Vault 更新内容时才需要 `parse.py`：

```bash
export KAOGONG_VAULT=/path/to/kaogongzhentizhengliu-main
python3 parse.py
```

配图另跑 `python3 img2webp.py`，可以中断重跑，已转换的会跳过。

### 部署成在线版本

本地跑只适合自己用。如果确实需要多人共用一套题库和复习进度，可以部署成在线版本：别人用浏览器打开就能刷，不用装 Python，也不用传题库。学习数据存在服务端，按账号隔离。

这台线上演示站就是这么来的：[kaogong-naoku-87074.app.workbuddy.host](https://kaogong-naoku-87074.app.workbuddy.host/?sharecode=DAYKONVYCN)。它只用于看界面效果，**数据不做保证**：跑在共享沙箱上，人多会卡，扩容或迁移时可能被重置，**不要在这里存唯一的复习进度**，重要数据定期从「设置 → 数据管理」导出快照。地址也不建议往公开群组里转，真题内容不适合公开扩散。

下面是我实际部署这个项目的完整过程，全程只需要对 WorkBuddy 的 AI 助手说人话。

**① 准备**

打开 [WorkBuddy](https://www.workbuddy.ai)，新建一个会话。沙箱工作区自带 Python 3.11 和 git，不用配环境。

**② 把代码放进工作区**

对助手说：

> 帮我克隆这个仓库到工作区：`git clone https://github.com/BigDog2712/kaogong-naoku-re1.0.git /workspace/kaogong-webapp`

也可以把仓库打包成 zip 直接上传。仓库带 340MB 题库和配图，克隆或上传要几分钟，等它跑完。

**③ 合并题库**

> 运行 `python3 assemble_db.py`，把分卷合并成 kaogong.db

大约 10 秒完成。看到「27,506 题」的提示就是成功了。

**④ 本地试运行**

> 运行 `python3 server.py`，然后预览页面

WorkBuddy 有内置浏览器预览，先自己刷几题确认正常。

本地学习数据存在 `dev-data/users.db`（`启动考公系统.bat` 和 `start.sh` 会自动设置 `KAOGONG_USER_DB`），和线上的 `data/users.db` 分开，本地怎么折腾都不影响线上账号。

**⑤ 发布为在线应用**

> 把 /workspace/kaogong-webapp 发布为应用，启动命令用 `PORT=$PORT python3 server.py`

发布时弹一次确认，确认后拿到公开链接。

**⑥ 分享使用**

把链接发给别人。打开是登录页，注册自己的账号，或者点游客模式直接开刷。每个账号的进度、错题本、笔记互相隔离。

**⑦ 日常更新**

代码或题库有更新时，在工作区 `git pull` 拉最新版，再发布一次即可覆盖线上版本，链接不变。注意：从外部资料拆题、替换解析、新增题目等题库改动**不得提交或上传 GitHub**（不符合许可规范），只在本机题库或私有部署中使用；能提交的只有代码和文档。

**更新前必须先备份。** 发布工具不一定保护运行时数据目录。即使源码仓库排除了用户库，也要在每次更新前把数据库取回自己电脑：

1. 用管理员账号打开线上应用，进入「设置 → 管理员：全库快照」，点击「立即创建快照」。
2. 等列表刷新，找到刚生成的快照，点击「下载」。确认文件大小大于 0，移到项目目录之外的安全位置，例如 `D:\kaogong-backups\`。建议再复制一份到独立磁盘或受控云盘。
3. 记下快照文件名和下载日期。含密码哈希的全库数据库不要提交到 Git，不要上传到公开仓库，也不要放进待发布的源码包。
4. 确认本机文件存在，再拉代码并发布。发布后用现有账号登录，核对账号数量和学习数据；发现异常立即停止，用管理员页面从已下载的快照恢复。

下载按钮不可用、或本机文件无法确认完整时，不要继续发布。不要用本地 `dev-data/users.db` 替代线上库。

本地自托管的更新方式不同：更新前停服务，用 SQLite backup API 对 `KAOGONG_USER_DB` 指向的实际用户库做一致性备份，确认文件完整后再更新代码。服务端快照只留在运行服务的机器上，不会自动传到你的电脑。

**本地自托管和在线部署怎么选：**

| | 本地自托管 | 在线部署 |
| :--- | :--- | :--- |
| 适合 | 自己一个人用 | 想分享给同学一起用 |
| 安装 | 需要 Python 3.8+ | 零安装，浏览器即用 |
| 数据位置 | 题库 `kaogong.db`（只读）加用户库 `data/users.db` | 服务端 SQLite，换设备登录不丢 |
| 访问 | `http://127.0.0.1:8300` | 公网地址，手机也能开 |
| 备份 | 用 SQLite backup API 备份实际用户库 | 管理员下载全库快照到本机，每次发布前必须完成 |

自 v1.5.0 起，线上默认用 `data/users.db`，本地启动脚本用独立的 `dev-data/users.db`。目录隔离能降低覆盖概率，但不能替代发布前把备份下载到本机这一步。

## 账号与数据

服务端按账号隔离数据，一个部署可以多人用，互相看不到对方的进度、笔记和收藏。

| 身份 | 说明 |
| :--- | :--- |
| 注册账号 | 用户名加密码登录，密码用 PBKDF2-HMAC-SHA256 加盐哈希存储，换设备登录即可续上进度 |
| 游客模式 | 免注册进入，自动分配匿名身份；换浏览器或清缓存就是新身份；可以在设置页升级成正式账号，数据不丢；退出即销毁 |

题量和进度都存在服务端 SQLite 里，浏览器只保存一枚登录令牌。

数据分两层：题库 `kaogong.db` 只读，学习数据在 `data/users.db`。备份有三种：

- 服务端每天 0 点后自动给全库和每个账号各留一份快照，全库保留 7 份，个人只留最新一份；
- 管理员可以在设置页「立即创建快照」、下载、恢复、删除全库快照；
- 个人可以把本人数据导出成 JSON 存到本机，也能从 JSON 合并恢复。

**更新前请先取回一份全库快照到本机并确认文件完整，再上传代码。** 自动快照存在服务器上，不能替代本机副本。

管理员权限、备份架构、运营面板和发布前检查的完整说明见 [docs/维护手册.md](docs/维护手册.md)。

## 配置

全部通过环境变量，默认值开箱即用。

| 变量 | 默认 | 用途 |
| :--- | :--- | :--- |
| `PORT` / `KAOGONG_PORT` | `8300` | 服务监听端口 |
| `KAOGONG_VAULT` | `../kaogongzhentizhengliu-main` | 原始题库 Vault 路径 |
| `KAOGONG_USER_DB` | `data/users.db` | 用户库位置，本地开发建议指向独立目录 |
| `KAOGONG_FRESH` | 未设置 | 设为 `1` 会完全重建数据库，清空学习进度 |
| `OPS_TOKEN` | 未设置 | 运营面板口令，至少 16 位才生效；不设则 `/ops` 返回 404 |
| `OPS_HIDE_ANON` | `1` | 运营面板只统计正式账号，设 `0` 把游客也算进来 |

题库更新后重跑 `python3 parse.py` 即可增量导入：进度按题号 `qid` 对应，已学的题自动保留，只有新增的题会以未学状态进入计划。

```
kaogong-naoku-re1.0/
├─ server.py              HTTP 服务、JSON API、图片服务（Python 标准库）
├─ sm2.py                 SM-2 间隔重复算法
├─ parse.py               题库 Vault → SQLite 导入器，只产出题库
├─ img2webp.py            题库图片转 WebP
├─ migrate_v2/v3.py       数据库结构迁移
├─ assemble_db.py         分卷题库合并器
├─ build_qbanks.py        导入题库元数据生成器（题库 → 分类 → 成员题号）
├─ build_ai_analysis.py   AI 解析生成器（调模型 → ai_json，断点续跑）
├─ import_ai_analysis.py  手工/离线 AI 解析导入器（JSON → ai_json）
├─ qbanks.json            导入题库清单（真题浏览按题库分类用，不含题目内容）
├─ start.sh               Linux / macOS 启动脚本
├─ 启动考公系统.bat         Windows 一键启动
├─ 重新导入题库.bat         题库更新后增量导入
├─ static/                前端单页应用
│  ├─ index.html
│  ├─ app.js
│  ├─ style.css
│  └─ sw.js               缓存自愈 Service Worker
└─ docs/                  截图、核查报告与维护文档
```

运行期生成、不进版本库的文件：`users.db`（首次启动自动生成）、`kaogong.db.bak-*`（拆分迁移前的备份）、`__pycache__/`、`*.log`。

## 常见问题

**换浏览器后进度不见了？**
注册账号后用用户名登录就能续上。游客身份绑在浏览器本地，换设备就是新身份，这是设计如此。

**能不能多人一起用？**
可以。各自注册账号，进度、笔记、收藏完全隔离。前提是你自己部署的实例，公开演示站人多会卡。

**占多大空间？**
代码约 600KB，后端一个 `server.py` 占 200KB，其余是前端资源。题库数据库 148MB（5 个 30MB 分卷），配图 192MB，都随仓库提供，克隆后合并一次即可。学习数据另存，初始不到 1MB。

**需要联网吗？**
不需要。零第三方依赖、零 CDN、零外部字体，断网照常用。

**上游 58,890 题，为什么这里只有 27,506 题？**
那是题目行数和去重后题量的差别，覆盖率 99.56%。展开上面的[核查说明](#题库)可以看到逐项账目。

**手机能用吗？**
可以，界面自适应，画笔和文字标注支持触屏。
