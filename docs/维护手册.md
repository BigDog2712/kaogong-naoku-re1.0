# 维护手册

这份文档面向部署维护者和后续接手改代码的人。普通使用不需要看。

**一条底线：用户库不能当作可重建的缓存。** 代码升级、前端重构、题库更新都不应该删除、覆盖或重置 `data/users.db`。

---

## 数据结构

| 文件 | 内容 | 改它会发生什么 |
| :--- | :--- | :--- |
| `kaogong.db` | 题库，只读挂载 | 不得用来存账号或学习进度 |
| `data/users.db` | 用户库：账号、会话、学习数据 | 删了或覆盖 = 所有人进度消失 |
| `data/backups/` | 备份根目录，只在服务端 | 发布时不应上传 |

`KAOGONG_USER_DB` 可以把用户库指到别的位置，本地开发建议这样做。旧版根目录的 `users.db` 只由启动时的迁移逻辑兼容处理。

用户库包含 `users`、`sessions` 等账号表，以及 `srs`、`reviews`、`notes`、`favorites`、`doubt_status`、`exam_history`、`study_time`、`discarded`、`user_settings`、练习记录和陪伴关系等业务表。`settings` 表保存全局维护标志，例如 `last_daily_snapshot`、`admin_uid`、公告版本。

表结构以 `ensure_tables()` 和 `migrate_v2.py` 为准。改表必须可重复运行，并且保留旧字段和旧数据。

## 发布前数据保护检查

每次向 WorkBuddy 或其他托管环境上传更新，按顺序走完这几步。这个检查不能被 `.gitignore`、`data/` 目录分离或服务端自动快照替代。

1. 用管理员账号登录生产实例，在设置页「管理员：全库快照」点击「立即创建快照」。
2. 在快照列表点击「下载」，把最新全库 `.db` 取回本机。确认浏览器下载完成、文件非零，记下文件名和日期。不要把它放进项目目录、Git 仓库或发布压缩包。
3. 确认备份文件保存在源码目录以外。重要的数据再复制一份到另一块磁盘或受控云存储。
4. 检查准备上传的目录或压缩包里没有 `users.db`、`data/users.db`、`dev-data/users.db`、`data/backups/` 或任何用户库副本。仅靠 `.gitignore` 不够，发布器可能上传整个目录。
5. 以上四步都完成后再上传代码。更新后用现有账号登录，核对账号和学习数据；发现异常立即停止操作，从本机备份恢复。

**本机备份没有下载并核验之前，不执行上传、发布或全库恢复。**

这份流程是人工门禁。如果所用发布工具没有可配置的 pre-deploy hook，不能声称工具已经自动拦截发布。

## 管理员

**管理员全库唯一，程序不会创建管理员账号。**

注册接口只在「库里既没有任何账号、也没有任何管理员」时，把第一个注册者设为管理员（`role='admin'`）。只要已经存在管理员，后续注册一律是普通账号，不会因为注册、升级或发布多出管理员。已有数据的库在升级时不会新增或重置任何账号。

启动时 `ensure_single_admin()` 只做收敛：如果库里意外出现多个 `role='admin'`，保留最早创建的真实账号（内置用户名 `admin` 视为旧版本遗留，会被降级），其余降为普通账号。一个管理员都没有时只打印告警，不造账号。确需指定时，用 `KAOGONG_PROMOTE_USER=<已存在的用户名>` 启动一次。

`role='admin'` 只用于授权管理账号和全库备份。这些接口都在服务端校验 token 和角色，前端隐藏面板不构成安全边界。

管理员可以修改自己或其他账号的名称、用户名、密码，普通账号只能管理自己的资料。删除账号会连带删除该账号的学习数据，不可撤销。管理员不能删除自己，也不能删掉最后一个管理员。

## 备份

设计原则：备份只存服务端，入口只留两个。个人侧只有「云端快照」和「本地 JSON」，管理员侧只有「全库快照」。不提供备份目录配置，避免出现"配了路径但只有服务器能写"的误解。

### 全库快照（管理员）

后台每天 0 点后创建一份全库一致性快照，写入 `data/backups/kaogong-<实例标识>/users-*.db`，保留最近 7 份。

写入后执行 `PRAGMA integrity_check`，校验失败的文件会被删除并重试。是否已完成用 `settings.last_daily_snapshot` 记日期判断，所以 0 点服务没运行时，启动后会补做当天那份，不会漏天。失败每 60 秒重试一次。

管理员在设置页可以「立即创建快照」、「下载」、「删除」。「恢复」会先用当前库生成一份 `-prerestore` 保护快照，再校验目标快照的完整性和 `users` 表是否存在，然后整库替换。全库恢复会替换所有账号和学习数据，执行前必须核对时间和文件。

### 个人云端快照

存放在 `data/backups/kaogong-<实例标识>/accounts/<uid>/account-YYYYMMDD.json`，按账号物理隔离。

每个账号只保留最新一份：当天重复保存直接覆盖，旧日期的文件在下次保存或重启整理时删除。每天 0 点自动生成，也可以「立即保存到云端」，支持下载、恢复、删除。

列表、下载、恢复、删除都从登录 token 取 uid，不接受前端传入他人 uid。路径穿越式的文件名一律返回 400。

### 个人本地备份

设置页「导出到本机（.json）」把本人复习进度、复习历史、错题计数、收藏、笔记、疑点、弃题、考试记录、每天学习时长存成本机文件。

「从本机文件恢复」按 `qid` 合并，同题取较新的记录，不会用旧备份覆盖更新的进度。合并规则：

| 项 | 规则 |
| :--- | :--- |
| 单题进度 | 按 `qid` 合并，`last_review` 较晚者胜，`correct` / `wrong` 取较大值 |
| 复习历史 | 按 `qid + ts` 去重，重复导入不产生重复记录 |
| 笔记 | `updated` 较晚者胜 |
| 收藏 / 弃题 | 已存在则跳过 |
| 学习时长 | 同一天取较大值 |

### 其他约定

- 删除账号（管理员删除或本人注销）会同时删除该账号的云端快照目录，服务器上不留残留。
- 快照是整库副本，包含所有账号。账号隔离由业务表的 `user_id` / `uid` 查询条件保证。普通账号拿到的云端快照和本地 JSON 只含本人数据。
- 建议升级前执行一次管理员全库备份，并定期把备份复制到与应用主机不同的设备。备份目录权限只对服务维护者开放。
- 服务端自动快照不是异机备份。

### 公告

管理员可以在设置页发布公告或更新说明。前端版本号变化时，服务端会自动发布内置的更新说明。

每个账号单独记录已确认的公告 ID，点「知晓」后不再重复显示。管理员发布新公告会生成新 ID，因此会再次通知所有账号。

## 维护注意事项

1. 发布和升级只更新代码和题库，不要删除 `data/`、`dev-data/`、`users.db` 或备份目录，也不要用开发机的用户库覆盖线上库。
2. 不要执行 `KAOGONG_FRESH=1`、重建用户库、手工删账号表这类会清空数据的操作，除非用户明确要求且已验证备份可恢复。
3. 复制 SQLite 文件要用数据库 backup API，或停服后复制。不要在并发写入时直接覆盖正在使用的数据库文件。
4. 数据库迁移要用事务、可重复运行、先快照，并验证旧版本数据和登录功能。题库导入不得写入用户库。
5. 密码只存 PBKDF2 哈希。任何接口、日志、备份界面都不得输出明文密码或哈希。
6. 初始化默认密码是公开的引导凭据，不适合公网长期使用。管理员首次登录后立即修改，生产环境应限制注册和访问面。

## 运营面板

给站长看的数据看板，只读、只聚合，不碰任何用户学习内容。

```bash
OPS_TOKEN="换成你自己的至少16位随机串" python3 server.py
# 访问 http://127.0.0.1:8300/ops
```

生成口令：`python3 -c "import secrets;print(secrets.token_urlsafe(24))"`

不设 `OPS_TOKEN` 时面板连存在都不暴露，`/ops` 直接 404。

### 看什么

| 区块 | 内容 |
| :--- | :--- |
| 指标卡 | 今日活跃、今日答题、正式账号数、今日新增，各带 7 天和 30 天对照 |
| 答题活跃度 | 按天柱状图，悬停看当日人数，区间可选 7 / 30 / 90 天 |
| 新增账号 | 按天柱状图，悬停区分正式账号与游客 |
| 用户做题量分布 | 100+、30–99、10–29、1–9、0 题五档的人数与占比 |
| 最近活跃账号 | 近 7 天有答题的账号，只显示昵称、类型、最近答题时间、累计题量 |
| 题库与存储健康 | 题量、完整性自检、进度行数、缺解析题数、库文件大小、日志模式、模块分布 |

### 安全设计

| 措施 | 说明 |
| :--- | :--- |
| 口令不进代码 | 只从 `OPS_TOKEN` 环境变量读，少于 16 位视为未配置 |
| 会话与用户体系隔离 | 面板会话只存进程内存，8 小时过期，上限 32 个；普通用户 token 无效 |
| 暴力猜解防护 | 同 IP 10 分钟内失败 8 次即锁定，每次失败额外延迟 0.4 秒，常数时间比对 |
| Cookie | `HttpOnly` + `SameSite=Strict` + `Path=/ops` |
| 接口只读 | 全部接口只发 `SELECT`，没有任何写库路径 |
| 不被搜索引擎收录 | `<meta name="robots" content="noindex,nofollow">` |

面板重启即失效（会话在内存里），部署更新后需要重新输入口令，这是预期行为。

## 前端版本号

改完 `static/` 下的文件后，同步更新 `index.html` 里的 `kg-app-ver`、CSS 和 JS 的查询版本串，否则浏览器会继续用缓存里的旧文件。
